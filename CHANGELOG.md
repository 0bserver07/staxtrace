# Changelog

All notable changes to StackUnderflow will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] — 2026-08-23

**The first release of the Rust engine, and the first release under the name
staxtrace.** The last published release, v0.9.2 (2026-05-29), was the Python
implementation; that tree now lives frozen on `python-legacy`. `main` is Rust.

### The product

- **Three binaries**: `stax` (the CLI), `stax-server` (the dashboard),
  `stax-hooks` (the injection fast path Claude Code spawns). All three are
  required, and all three are relocatable — every data file they read is
  compiled in, proven by running them with the source tree unreachable.
- **20 provider adapters**, always on, no opt-in flags.
- **The memory layer** — `stax memory decisions/file/worked/sessions/ask` —
  behind a versioned, golden-fixtured JSON envelope any harness can parse.
- **The agent telephone** — `stax msg send` / `inbox`, store-and-forward over
  ssh, delivered into a live agent turn by the injection hooks.
- **Agent remotes** — `stax remote add`, `--at <remote>` on the read-only
  memory/resume namespaces, and `stax observe <remote>` to tail another
  machine's session live.

### The rename

Every user-visible surface now says staxtrace: the CLI, the dashboard, the
docs, the skills, the injected banners. Identifiers moved with compatibility
kept, deliberately and permanently:

- `STAXTRACE_*` env vars are canonical; `STACKUNDERFLOW_*` is still read.
- Hook ids are `staxtrace-*`; a pre-rename `settings.json` still fires, is
  recognised as ours, and is rewritten in place by `hooks install`/`repair`.
- Envelopes are `staxtrace.memory/1` (and `.resume`/`.anchor`/`.observe`);
  readers accept the pre-rename name, because the envelope crosses machines and
  a peer may be older.
- The launchd label is `com.staxtrace.backup`; the old label is torn down on
  disable rather than left running.
- `~/.stackunderflow/` is unchanged and still resolved. `$STAXTRACE_HOME` and
  `~/.staxtrace/` are honored if you move it; no data is moved for you.

### Fixed in this release

- `status`/`today`/`month` no longer fail outside a source checkout — the rate
  card falls back to the copy compiled into the binary.
- `hooks install` writes the native `stax-hooks` command; the earlier form
  invoked a Python entry point that a Rust-only install does not have.
- Codex sessions carry the human's first message as their title instead of the
  agent's own framing, and real durations instead of zero.
- Project dashboards scope their findings and anomalies to the project.

### Known

- 11 models have no rate card entry (the cached LiteLLM overlay is stale), so
  spend is understated; `stax pricing doctor` reports the exposure by model.
- `stax reindex` is slow on large stores.

## [Unreleased]

### Added

- **`stax audit --allow-host HOST`** (repeatable; also `STAXTRACE_AUDIT_ALLOW_HOSTS` and an `audit_allow_hosts` list in config.json) — the known-remote allow-list Spec 28 §8.4 calls mandatory. **`git remote add … → git push`** is a transcript rule family now, `stax audit` reads every provider's tool-call shape (Codex, Gemini, Grok, Pi, Droid) instead of only Claude's, and a veto exported in the shell counts the way the agent itself counts it.
- **The Rust port of the entire product (`rust/`, campaign branch): `stax`, `stax-server`, and `stax-hooks`.** A byte-parity reimplementation verified against this Python tree case by case: the CLI answers 1,100+ recorded invocations byte-identically on real store states (stdout, stderr, exit codes); the server answers 790+ endpoint cases with zero divergences while serving the unmodified React bundle; ingest, pricing, marts, and stats are proven bit-for-bit on live data; hooks fire in 2–5 ms where the interpreter floor alone exceeded real hook budgets; sync round-trips age-encrypted shards across implementations. The binaries stand alone — every data file they need is compiled in, proven by running them with the Python tree unreachable. Divergences (~460 ledgered) are each disposed bug-for-bug, fixed, or ruled; the maintainer's rulings of 2026-08-04 are executed, including CORS, both trailing-slash 307 classes, encoded-path routing, pydantic-grammar query parsing, and the stats memo (whose warm path now outruns the reference). Entry points: `stax` is the Rust binary through the soak; `stackunderflow` remains this Python package.

### Fixed

- **`stax audit` no longer reports a veto that IS set as at-risk, and names the right agent.** An adversarial review of the first build found three launch blockers, each fixed with regression tests. The hand-rolled TOML reader could not see dotted keys, inline tables, quoted sections or arrays of tables — a fully vetoed Grok config audited as "unreadable" and a Codex `analytics.enabled = false` audited as at-risk — so TOML now goes through the `toml` crate already in the workspace graph. Transcript findings were keyed by rule alone, so `provider` was whichever agent ran first; they key on (provider, rule) and name the session the evidence came from. Raw sockets (`nc HOST PORT`, socat), ssh aliases (`scp x backup:/tmp`), `sudo`/`env`/`sh -c` wrappers and short-flag bundles (`-sTd`) all evaded detection; none do. Also fixed: the claude signature looked for an opt-in OTel key and reported nothing about the default-on usage metrics and error reports; Gemini moved its key under `privacy` (auto-migrated since 2025-09) and the old spelling reported opted-out users as at-risk; gh-copilot's YAML was parsed with the TOML reader and errored on line 1 every time; signature paths were not confined to the home, so a third-party pack could make `--json` echo `/etc/passwd`; and the transcript query ordered the `messages` UNION ALL view, materializing the whole store. Private networks, tailnets and `localhost` are no longer "remote"; `.env.example` reads no longer escalate; bodyless `-X POST`, `gh release upload` and `grep -F pastebin.com` are no longer findings. Every row prints its evidence, and every shipped check has a positive and a negative fixture in CI — the README's claim, now enforced by a test.
- **`/api/plan`'s spend memo now keys on the calendar day** — previously an answer computed before local midnight was served after it until process restart.
- **`?per_page=0` on `/api/search` and `/api/qa`** returned a 500 (division by zero); it is now a pydantic-validated 422 (`ge=1`), with the silent 100-ceiling clamp unchanged and pinned as contract.
- **Context-injection hooks open the session store read-only**, as their documentation always claimed; previously every hook fire opened read-write and touched WAL state.
- **`resume` output order is a documented contract** (`last_ts DESC, session_id`) instead of planner luck — `ANALYZE` on a store could previously reorder up to a third of the rows.

- **Sync without a bucket — `ssh://` as a sync transport.** `sync init --bucket ssh://[user@]host[:port]/abs/path` now syncs encrypted aggregate shards between machines you already own, with no S3 bucket, no cloud account, and no credentials to leak. The zero-knowledge property is unchanged: `runner` still encrypts every shard with `age` before the transport sees it, so the remote host holds only ciphertext exactly as a bucket would — this is a transport, not a security boundary. Implemented as a fourth `ObjectStore` (`put`/`get`/`list`/`delete`) in `sync/ssh_store.py`, so `push`/`pull`/`merge`/manifest logic is untouched; `bucket.store_from_url()` dispatches on scheme and `runner`'s two construction sites go through it. Deliberately dependency-free — everything shells out to the system `ssh`, so agent keys, `~/.ssh/config` aliases, ProxyJump and non-standard ports all behave as they do in a shell, and `BatchMode=yes` means a password-needing host fails fast instead of hanging a scripted push. `boto3` is no longer required for an `ssh://` destination (the `[sync]` bucket dep is now scheme-aware), destinations are validated at `init` rather than at first push, and `put` writes to a `.part` file then renames so a reader never sees a half-written shard. **Missing objects are signalled by remote exit code, never by empty stderr** — real sshd installs emit banners and advisories on every connection (found against a host printing OpenSSH's post-quantum warning), which made every absent object look like a transport failure and would have hard-failed the first `pull` against a fresh peer, where a missing manifest is the normal case. 23 tests, including that regression and one real `ssh` invocation against a closed port.
- **`backup create --to ssh://…` — replicate a finished backup to another machine.** Distinct from sync, and the help text says so: one direction, whole artifacts, no merge, and it carries raw session data that sync deliberately never touches. Passes `--link-dest` at the *remote* previous generation, so the replica gets the same zero-disk-for-unchanged-files property as the local backups. Replication runs last and is non-fatal to the local backup — a network failure can never invalidate a backup that already succeeded on disk — and the destination is validated before any copying starts, so a typo costs 0.2s instead of a full `~/.claude` mirror.
- **The data directory is relocatable — `$STACKUNDERFLOW_HOME` / `start --data-dir`.** The store, indexes, and config no longer have to live at `~/.stackunderflow`: point the whole app at any dataset — one copied off another machine, or a backup's `stackunderflow-state/` — and serve analytics straight out of it. `settings.app_dir()` is the single resolver (`$STACKUNDERFLOW_HOME`, else `~/.stackunderflow`) and **every** site that recomputed `Path.home() / ".stackunderflow"` by hand now derives from it — 14 in total across `deps.store_path`, `cli._STATE_DIR` (and `_BACKUP_DIR`), `server.py`'s cold-cache sweep, `search_service.SEARCH_DB_PATH`, `qa_service.QA_DB_PATH`, `embeddings.EMBEDDINGS_DB_PATH`, `etl.lock.DEFAULT_LOCK_PATH`, `model_manifest._STORE_PATH`, `pricing_service` (cache dir, `pricing.json`, and its own store path), `currency`, `cursor_cache`, `skill_recommender`, `bookmark_service`, and `tag_service`. Fixing only some of them is worse than fixing none: with the store redirected but the sidecars still on `$HOME`, search and Q&A silently open *fresh empty* databases while the real indexes sit unread, and pricing reads a different store than the dashboard. A `--data-dir` run now creates nothing under `$HOME` at all (verified by deleting `~/.stackunderflow` and confirming it is not recreated). Because those paths bind at import, `--data-dir` validates the directory and then **re-execs** with the env var set rather than reassigning half-initialised globals — the env var stays the one authoritative mechanism, and the exec can't loop because it returns early when the environment already matches. `_save()` gained `parents=True` so a nested `--data-dir` works on first write. Read-only with respect to the dataset; no migration, and unset behaviour is byte-identical to before.
- **`stackunderflow resume [PATH]` — session/resume ids for every coding agent under a path.** Give it a workspace folder (e.g. `…/new_terminal/`) or stand inside a project: recent sessions are grouped per provider with each agent's REAL resume invocation rendered — `claude --resume <id>`, `codex resume <id>`, `cursor-agent --resume <id>` (templates are data in `adapters/capabilities.json`, each verified against the actual CLI's `--help`; grok is latest-only via `grok --continue`; agents with no known resume command still list their session ids, never an invented flag). Matching happens in slug space — decoding slugs to paths is lossy (`dev_dev` folds to `dev-dev`), so the query path is encoded instead, which also makes underscore/hyphen paths just work; of ancestor projects only the nearest is kept, so a home-directory catch-all can't swamp results. `--json` emits a `stackunderflow.resume/1` envelope for agents; read-only.
- **`doctor` delivery scoreboard** — `stackunderflow doctor` now renders, next to the store health check, a per-provider delivery table: *disk sessions → base messages → usage_events → marts*, with verdicts `OK` / `GAP` (billable rows loaded, zero events — the class of silent failure that left codex dark for months) / `NO_BILLABLE` (rows parsed fully but the source contains no assistant usage to price — correct zeros, not a gap) / `DISK_GAP` (on disk, never ingested) / `EXEMPT` (data-driven via `capabilities.json`) / `EMPTY`. `--fail-on-gap` turns delivery gaps into a non-zero exit for CI/pre-release gates; the default exit still reflects store health only. The check is read-only, crash-free (enumerate failures degrade to `?`), and testable via an injectable adapter list.
- **Backup covers every agent, not just Claude** — `backup create` still mirrors `~/.claude` at the backup root (existing restores unaffected) and now also copies every other registered adapter's source roots under `sources/<adapter>/`, with `sources/manifest.json` mapping each subdir back to its original absolute path. Roots are self-declared per adapter (`source_roots()` / `watch_paths()` — no central path list); a missing dir or broken adapter skips that adapter only; rsync `--link-dest` keeps unchanged files at zero extra disk. `backup restore` now excludes the backup-internal `sources/` and `stackunderflow-state/` dirs instead of injecting them into `~/.claude` (pre-existing flaw for the state dir).
- **Claude's slug→dir fallback stays Claude's** — five sites (`infra/discovery.py`, `routes/projects.py` ×2, `routes/sessions.py`, `store/queries.py`) hardcoded `~/.claude/projects` as the fallback for any project with no stored path, silently branding non-claude projects with an invented claude dir and ignoring `CLAUDE_CONFIG_DIR`. All five now derive from the new `adapters.claude.default_projects_root()` (env-honoring) and apply it to claude/legacy rows only — a non-claude project with no stored path resolves to `""` (unknown), guarded so it can never be treated as the cwd. `reports/optimize.py`'s per-project CLAUDE.md scan derives from the same accessor.
- **Hook slug-collision preference is host-declared, not baked into SQL** — `hooks/_resolve_project_id` had `ORDER BY (provider = 'claude')` hardcoded; the preference is real (this module IS Claude Code's hook surface) but now lives as a module-level `_HOST_PROVIDER` self-declaration passed as a query parameter, so another host's hook surface supplies its own provider.
- **gpt-5.4 rate corrected with effective dating — history keeps the rate it was billed at** — the in-code table carried output $20/M while the official page now lists $15/M. `data/models.toml` gains a `GPT_54` entry with two effective-dated rows: $20/M until 2026-04-26, $15/M from then (boundary anchored to the gpt-5.5 launch window; full evidence trail — OpenRouter launch date Mar 5 2026, this repo's own contemporaneous $20 record in commit `5749324` of Apr 30, official page fetched 2026-07-09, and one conflicting secondary source — is documented at the entry and the boundary is adjustable if a primary announcement date surfaces). `OpenAIPricer` gains an `at_ts`-threading `compute()` override mirroring the Anthropic pricer, and `rates_for` is manifest-first so a family present in both the manifest and the in-code enum resolves from data. The price-book equality gate re-proves book-path == in-code across the dated rows. Known edge flagged: undated `rate_card`-source book rows outrank dated manifest rows on the store-backed path, so server-primed pricing of *newly ingested* pre-boundary events would use the current rate; the CLI backfill path (which prices history) is dated-correct.
- **gpt-5.5 priced — identity + rates as manifest data** — `data/models.toml` gains an exact-`ids` matching field (token sets collapse duplicates: `gpt-5.5` → `{gpt,5}`, indistinguishable from `gpt-5` by tokens) and a `GPT_55` entry at the official published rates ($5.00/M input, $0.50/M cached input, $30.00/M output, no cache-write billing; developers.openai.com/api/docs/pricing, fetched 2026-07-09). `OpenAIPricer` now consults the manifest before its in-code table, so future OpenAI models are manifest edits, not code. `gpt-5.5` joins `[canonical_ids]`, so its events price as `rate_card` instead of $0 `unknown`. Known open question flagged for the maintainer: the in-code gpt-5.4 output rate ($20/M) disagrees with the official page's current $15/M — needs an effective-dated correction once the change date is known.
- **Model→pricer routing derived, not hand-written** — `costs._provider_for_model`'s if/elif prefix ladder is gone: exact ids resolve through `models.toml [canonical_ids]` (each group name IS the pricer key), wild ids through prefix/substring hints the pricers now declare on themselves (`model_id_prefixes` / `model_id_substrings`, longest hint wins) — 74-input behavior snapshot verified identical before/after. Price-book precedence corrected to **live > dated manifest family > undated rate_card snapshot** in both lookup paths, closing the flagged edge where an undated current-rate row could shadow a dated historical correction. The e2e normalizer harness now loads every provider's fixture from checked-in data packs (`tests/fixtures/beta_normalizers/`), and the docs got a truth pass (beta-flag claims removed everywhere except two explicit "superseded/retired" historical notes).
- **Model identity is data, not code (hardcode-census follow-through)** — three more hand-maintained tables extracted: (1) the what-if/routing model menus, previously two hand-synced copies in `services/whatif.py` and `reports/prescribe.py`, now load one catalog (`infra/model_candidates.json`, explicit `routing_candidate` flags; sets preserved byte-identically); (2) `_CANONICAL_IDS` (52 model ids feeding `RATE_CARD` membership) moved out of `infra/costs.py` into the existing data manifest (`data/models.toml` `[canonical_ids]`, loaded via `model_manifest.canonical_ids()`; order and `RATE_CARD` keys verified byte-equal before/after); (3) `report --provider`'s stale 7-name `click.Choice` now derives from the adapter registry. Frontend: `providerStyle.tsx` had `cursor_agent` (underscore) as its color key — every cursor-agent chip rendered gray since it shipped (the fourth layer hit by the same underscore drift); fixed, and unknown providers now get a deterministic hashed color instead of falling through a stale hand-list.
- **Every coding-agent adapter is always on** — the `STACKUNDERFLOW_BETA_*` opt-in gating is removed; all 20 adapters register unconditionally (an absent source dir simply enumerates nothing). The registry is now **self-discovering**: `adapters/__init__.py` walks the package at import time, so a new adapter file registers itself — no import list to extend, no flag, no way to ship an adapter that silently never registers. The curated per-adapter fidelity table moved out of Python into package data (`adapters/capabilities.json`, loaded + validated by `services/support_matrix.py` with per-entry `basis` source citations), so agent names are data, not hardcoded literals. `watch_paths()` became an optional `WatchableAdapter` capability, matching the watcher's existing getattr contract.
- **Normalizer registry is self-discovering too** — the second hand-written per-agent table (20 imports + 21 `register("name", Class)` lines in `etl/normalize/__init__.py`) is gone: every concrete `Normalizer` with a `provider_name` registers itself, `provider_aliases` covers shared parsers (Pi/OMP), and the class attribute is the single source of the provider key. The old hand-written block is exactly what shipped cursor-agent's normalizer under `cursor_agent` while the adapter emits `cursor-agent`. Walk-vs-registry contract tests added; `CursorAgentNormalizer.provider_name` corrected.
- **Pricer registry is self-discovering too (third and last hand-written table)** — `infra/providers/__init__.py`'s 20 imports + 19 hand-made singletons + 21-key name map are gone: a pricer registers by declaring `provider_name` on its class, with `provider_aliases` mapping extra strings to the same singleton (`claude`→Anthropic, `codex`→OpenAI, `omp`→Pi). `get_pricer(record.provider)` now resolves adapter provider strings directly, so the *chained second map* (`_PROVIDER_TO_PRICER` + `_provider_for` in `etl/normalize/base.py`) is deleted outright. The existing registry behavior tests (case-insensitivity, Anthropic fallback, alias-shares-singleton) pass unchanged.
- **Worktree intelligence (campaign #8)** — the tool now knows every git worktree: `stackunderflow worktrees list` / `GET /api/worktrees` scan each project's worktrees read-only (batched `git worktree list`, an allowlisted git chokepoint that refuses any mutating command) and report branch, age, dirty files, unique commits vs the default branch, attributed sessions + cost, and a conservative verdict (`ACTIVE` / `HAS_UNIQUE_WORK` / `MERGED_SAFE_TO_PRUNE` — never "safe" on any git error). Prune commands are copyable previews only; the tool never deletes git state. A new beta **Worktrees** dashboard tab surfaces all of it.
- **Phantom-project roll-up** — sessions run inside worktrees used to appear as separate sibling projects (e.g. `…-myrepo--claude-worktrees-fix-x`), fragmenting per-project cost. `/api/projects` now folds fragments into their parent row (`worktree_sessions`, `worktree_cost`, `worktree_count`; fold happens before pagination so counts stay truthful; `?include_worktrees=1` shows the raw list). `stackunderflow worktrees attribute` (or `POST /api/worktrees/attribute`) stamps the new v027 `projects.worktree_of` column; unmatched fragments always stay visible rather than being guessed into a parent.

- **Active-recall hooks** — an opt-in PreToolUse hook (`hooks install --inject`) that, before an Edit/Write/Bash runs, queries `stackunderflow memory file <path> --json` and injects that file's past failure modes into the live agent's context. Hard-capped injection size, 1.5s hard timeout, and always-exit-0 silent no-op on any error, so it can never block or slow a tool call.
- **Coding-health tab (`Health`, beta)** — cross-session pattern mining at `/api/patterns`: per-file failure rates across sessions, recurring error signatures with resolution hints, and command failure clusters. Window-bounded (default 90d, max 365d); `file_risk()` is exposed programmatically for the recall hook.
- **Prescriptive cost (Optimize surface)** — `/api/optimize/prescriptions` turns waste findings into actions: model-routing recommendations built from per-model spend + v026 reasoning-token attribution (with dollar deltas priced through `compute_cost`, never invented), and a CLAUDE.md slimming preview (`POST /api/optimize/claudemd-preview`) that emits a unified diff + per-rule savings. Preview-only by construction — the server never writes user files (enforced by an AST source-scan test).
- **Backup state capture** — `backup create` now copies the four critical `~/.stackunderflow` artifacts (`store.db`, `search_index.db`, `qa_pairs.db`, `tags.json`) into `<backup>/stackunderflow-state/` via the SQLite online-backup API. Previously a fresh backup failed its own `backup verify` and a restore silently lost search/Q&A/tags.
- **Context-window replay (issue #96, beta)** — reconstruct what the model "saw" at a point in a session. `stackunderflow context-replay <session> --at <seq>` / `GET /api/context-replay/{session}?at=<seq>` return the ordered message sequence that had accumulated as the model's context up to that turn — each turn's role, a content preview, an estimated token footprint, its tool calls, and a running token total. Read-only + advisory (an unknown session is empty-but-valid, never an error); same-project fencing and a per-session read-through cache like `/api/forks`; `--json` emits the shared `stackunderflow.memory/1` agent-output envelope. A new beta **Context Replay** dashboard tab scrubs the `seq` cutoff and watches the token total grow. MVP semantics = "the session's message sequence up to `seq`" (harness-side context eviction is a later refinement).
- **Multi-device sync (issue #100, opt-in)** — sync your cost/usage **aggregates** (never raw transcripts) across machines through your own S3-compatible bucket, client-side-encrypted with `age` (zero-knowledge; the bucket sees only ciphertext). `stackunderflow sync init/push/pull/status` (import-guarded `[sync]` extra). Push writes only encrypted mart shards under this device's prefix (two-phase manifest commit, skip-if-unchanged); `pull` merges peers into a unified view at `GET /api/sync/overview?scope=all-devices` — aggregates union at the stable `(provider, slug)` grain, sessions deduped by id. Default-off and byte-identical when unconfigured; additive `v028`/`v029` migrations.
- **Proactive nudges (issue #97, opt-in, default-off)** — before a Bash command that has failed in a cluster of your past sessions (or after a recurring error signature), a hook injects a one-line, locally-derived heads-up ("`npm install` has failed in 3 recent sessions here — mostly Timeout"; "this error recurred in 4 sessions; the ones that moved past it ran X next"). A governance layer (per-session dedupe/cap, cross-session cooldown, dismiss-driven adaptive quieting; state in a file-locked JSON, never the DB) prevents nudge fatigue; hooks stay fast, LLM-free, silent-on-failure, and never block a tool. A "What almost bit me" panel in the Health tab surfaces recent would-have-fired nudges with dismiss controls.

### Fixed

- **`project_mart` now covers every project, the gap is observable, and zero-record files stop minting ghost projects.** Mart membership used to equal "has `usage_events`", so 91 of 334 real-store projects — 62 legacy history pseudo-sessions with real prompt text, 13 whose provider deliberately emits no usage events, 12 codex ghosts, 4 normalizer-guarded — were invisible to every mart-backed read path, and any one of them was enough to trip the `include_stats` fallback. Three linked fixes: (1) the mart refresh seeds a zero-cost row for every uncovered project (totals truthfully 0, message dims filled from raw messages, steady state costs one indexed anti-join and no write — covered projects never re-enter the dims pass); (2) `etl status` (CLI + API) gains a `coverage` block — `projects_without_mart` with sample ids — because the gap was previously invisible on every health surface; (3) the ingest writer creates project/session rows only once a file actually yields a record — a Codex rollout with no `cwd` that read out empty used to leave a permanent path-less `codex-<uuid>` ghost project behind (zero-record files are still marked processed, and an already-known project still gets its `last_modified` advanced). Known trade, recorded in the task index: seeded rows carry NULL first/last timestamps (their dates come from messages, not events) and their dims refresh only at seed or rebuild time.
- **`/api/stats` finally has a warm path — 4.0s per call → ~80ms warm on the 17K-message stress project.** It was the last consumer of the full collector pipeline still recomputing on every request: `/api/cost-data` and `/api/tool-distribution` shared the RANK-11 memo (84ms warm) while the dashboard's single slowest endpoint paid ~4s every time, warm or not. `/api/stats` now rides the same memo entry — same ingest signature (max `last_ts` + summed `message_count` over the project's sessions), so a warm hit can never serve pre-ingest numbers, and the memo's deep copy keeps the route's in-place trims (daily cap, heavy-block strip, currency, `include=` filter) from poisoning the shared entry — pinned by a regression test that strips via `/api/stats` and then proves `/api/tool-distribution` still reads the intact distribution without a recompute. Measured: 5.19s cold → 78–122ms warm, `days=`/`include=` variants included.
- **`/api/projects?include_stats=true` no longer hangs on stores with mart-uncovered projects.** A single project without a `project_mart` row routed the whole request through unfiltered GROUP-BY aggregates over every message row — >180s and a wedged server on a real 382K-message store (91 uncovered of 334, most carrying no billable messages at all, so the scan bought nothing). Both bulk helpers now take an explicit `project_ids` scope and every route callsite passes one; the scope is shaped as the `session_fk IN (SELECT id FROM sessions WHERE project_id IN (…))` list subquery — not a predicate on the joined `sessions` row, which the partitioned `messages` view's planner cannot push down — so each partition seeks its `(session_fk, seq)` index: measured 1141ms → 10ms (lite stats) and 1047ms → 2.5ms (cost) for the fallback pass, and ~55ms end-to-end for the endpoint that previously hung, all 303 rows carrying stats. The worktree roll-up's lazy cost fallback — the same full scan, but reachable on the `include_stats=false` path — is scoped identically. An empty scope runs zero SQL and is never promoted to "all projects"; ids are chunked at 900 to stay under SQLite's bound-parameter floor.
- **Cross-vendor sessions are priced on the model's rate card, not the tool's.** `projects.provider` records which tool wrote the transcript, and the terminal single-vendor pricers never answer "unknown" — so a `pi` project logging `claude-opus-4-7` billed through the GPT fallback at 2.7× under the correct rate (live rows on the maintainer's store), and a `claude` project logging `gpt-5` under-billed the other way. `resolve_pricing_provider()` lets a *definite* model→vendor match win, with three guards that keep every correctly-delegating shell bit-for-bit unchanged: no definite match keeps the recorded provider (an unrecognised id keeps its shell's honest $0 instead of being invented into existence), a vendor pricer that can't price the id never overrides a shell that can, and equal rates keep the shell. Applied in `bulk_project_cost` and the raw global-stats scan so the project list and the Overview total cannot disagree about the same row.

### Fixed — Agents tab synthesised "teams" from unrelated projects (project-scoping bug)

The v013-fallback `_list_team_sessions_scan` returned every session in any project that had a sidechain message anywhere. SutroYaro has 0 sidechain but 374 `Task` tool calls; the tab returned 10 unrelated sessions from `mycelium-ecosystem` and `ComedyCatalouge`. ### Fixed — /api/yield route timeout on real-store-shape projects

`/api/yield` (and the underlying `services.yield_tracker.compute_yield`) was timing out at 15 s on a real store with ~95 sessions in a single project (~250 K messages, ~150 K usage events). cProfile pinned 87 % of the time to `subprocess.run` — the v1 pipeline issued **one `git rev-parse` per session plus up to four further `git` invocations per *classified* session** (`git log` window, `git show` for commit time, `git log --grep=revert` per candidate sha, `git merge-base --is-ancestor`). With sessions sharing the same `cwd`, the same git work was redone hundreds of times.

The pipeline is now **batched per distinct `cwd`** instead of per session:

- One `git rev-parse` per distinct cwd (cached for the request's lifetime).
- One `git log --since={earliest}` per distinct cwd, format extended to `%H|%cI|%s` so the per-session windowed lookups answer from an in-memory list — the separate `git show` per candidate is gone.
- One `git rev-list HEAD` per distinct cwd materialises the reachability set; per-session `--is-ancestor` shells are gone.
- One `git log --all --grep=revert -i` per distinct cwd builds a short-sha hit set; per-session `--grep` calls are gone.

Per-session SQL was also batched: `_first_cwd_for_session` (one `SELECT … LIMIT 1` per session against the partitioned `messages` view) is replaced by a single `ROW_NUMBER() OVER (PARTITION BY session_fk ORDER BY seq)` window query that returns at most one row per session.

A defensive per-project session cap (`STACKUNDERFLOW_YIELD_MAX_SESSIONS_PER_PROJECT`, default 200, set to `unlimited` to disable) trims the most-recent N sessions for a single pathological project so the route stays bounded even if a future store carries thousands of sessions in one period.

Timing measured against a `.backup`-copy of the maintainer's real store (1237 sessions, 270 K messages, 145 distinct cwds):

| ------------------------- | ---------- | ---------- |
| `month` / all projects    | 6.62 s     | 1.47 s     |
| `all` / all projects      | 42.16 s    | 12.6 s     |
| `month` / single project (87 sessions) | n/a (route timed out at 15 s in original report) | 0.24 s |
| `all` / single project (87 sessions)   | n/a        | 0.35 s     |

Public `compute_yield` / `yield_summary` / `to_dicts` / `dumps` API and `YieldEntry` shape are unchanged. Existing route currency conversion + the `warning` field stay untouched. Two new latency-regression tests under `tests/stackunderflow/services/test_yield_perf.py` (`@pytest.mark.slow`, deselected by default) pin the bulk-per-cwd subprocess contract: a single project with 150 sessions on the same cwd must not issue more than 1× `rev-parse` / 2× `log` / 1× `rev-list` and must complete in under 2 s.

### Added — mode recommender (heuristic v1)

New service `stackunderflow/services/mode_recommender.py` recommends the cheapest model that fits a task, based on the user's own past sessions. Confidence in [0, 1] multiplies three terms: sample-size (`min(1, n/5)`), spread (`1 - σ/μ` of pick costs, clamped), cost gap (`(median_other - median_pick) / median_other`, clamped). ### Added — Playback v2 backend: virtual-filesystem reconstruction at a point in time

Closes HANDOFF follow-up #8 (backend half). The v1 playback surface (`GET /api/playback/{session_id}`) returns the ordered tool-call event stream the dashboard scrubber steps through; the v2 endpoint reconstructs the *file contents* at any moment in that stream by replaying the session's Read / Write / Edit / MultiEdit / NotebookEdit calls. No schema migration — the inputs all live in `messages.raw_json`.

- **New route** `GET /api/playback/{session_id}/fs?at=<iso>&paths=<csv>&include_content=true|false` in `stackunderflow/routes/playback.py`. Response shape: `{session_id, snapshot_ts, files: {path: {content?, byte_count, last_modified_ts, operations_applied, reconstruction_complete}}, warnings}`. 404 when the session isn't in the store; 422 when `at` can't be parsed; 200 with `files: {}` when the session has no file-touching tool calls before `at`. `include_content=false` returns the metadata (sizes, op labels, completeness flag) without the file bodies for "which files changed" queries.
- **Service** `stackunderflow/services/playback_fs.py` — `reconstruct_fs_at(conn, session_id, *, at, paths, include_content)`. Walks `messages` for the session in `seq` order, applies each FS-touching tool call up to and including `at`. Read seeds initial content (with Claude Code's `cat -n`-style line-number prefix stripped so subsequent Edits match the raw bytes). Write replaces full content. Edit / MultiEdit substitute `old_string → new_string` against the current content; an Edit without a prior Read records the new_string as best-effort working content and marks `reconstruction_complete = false`; an Edit whose `old_string` doesn't match the current content is skipped with a warning ("substitution skipped") and prior state preserved. MultiEdit applies each sub-edit in order with per-edit miss warnings. NotebookEdit accumulates a JSON `{cell_id: source}` map (notebook is never marked complete — we only see touched cells, not the full `.ipynb` tree). The `replace_all` flag is honoured on both Edit and per-MultiEdit sub-edits.

### Changed — outcome-aware discovery gains a confidence score + tighter heuristic (HANDOFF #9)

Closes HANDOFF follow-up #9. The transcript-fallback heuristic behind `find-sessions-where-action-worked` / `find-failure-modes-for-file` was too permissive: any session that simply ended without an explicit complaint was confidently surfaced as "worked". The fix is a confidence score on every `OutcomeMatch` plus a default filter on it.

- **`OutcomeMatch.outcome_confidence: float` in `[0.0, 1.0]`.** Additive; the existing `outcome` field (`"worked"` / `"failed"` / `"reverted"` / `"uncertain"`) keeps its string-shape contract. New rubric: `1.0` reserved for the `captured_events` deterministic path (future hook integration); `0.8` for an explicit in-vocabulary user phrase within the lookahead window; `0.5` for an agent revert tool call (`git revert` / `git reset --hard` / `git checkout --` / `git restore`) on the same file; `0.3` for "session continued or ended with no signal" (the old too-permissive case); `0.0` when the anchor was already the last recorded turn.
- **Default `min_confidence=0.5` filter on both service functions** (`stackunderflow.services.discovery.DEFAULT_MIN_OUTCOME_CONFIDENCE`). Rows below the threshold stay in the database but are filtered out at the surface so silence is no longer mistaken for success. Power-users can opt back into the legacy reading with `min_confidence=0.0`.
- **CLI `--min-confidence` + `--verbose / -v` flags** on both `find-sessions-where-action-worked` and `find-failure-modes-for-file`. `--format json` always carries the `outcome_confidence` field; the text-format branch shows it inline only when `-v` or an explicit `--min-confidence` was passed (keeps the human-facing default tidy).
- **MCP tools gain a `min_confidence` arg** (`None` → service default; out-of-range values clamp into `[0, 1]`). The two outcome-tool dicts now always carry `outcome_confidence` so an MCP-side consumer can filter further regardless of the server's threshold.
- **Expanded signal vocabulary.** Negative: `broke` / `broken` / `failing` / `mistake` / `error` / `regression` / `❌` / `👎`. Positive: `tests pass(ing)` / `fixed` / `solved` / `correct` / `+1` / `👍` / `🎉` / `✅` / `✓`. Revert: `try again` / `try a different`. Keyword regex builder now drops the `\b` boundary on tokens that start or end with a non-word character so emoji and `+1` actually match.
- **8 new adversarial tests** (`TestOutcomeConfidenceAdversarial` in `tests/stackunderflow/services/test_discovery.py`) pin the per-row confidence at each ladder step and the default-threshold filter behaviour. The existing classify-outcome tests update to unpack the 4-tuple `(outcome, evidence, msg_id, confidence)` return.

No schema migration; the change is pure code over the same `messages` view.

- **Fingerprint cache for the Cursor (vscdb) adapter.** Cursor's `state.vscdb` lives at `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb` and grows monotonically — on a busy developer's machine it can easily hit 1+ GB.
